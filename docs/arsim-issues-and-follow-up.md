# AS4 / AS6 自动开发测试：问题与后续优化

记录日期：2026-11-18。测试范围为 p801 AS4/J4.93、p102 AS6/6.7.8 的构建、仿真安装、在线下载及 PVI 读取；实际命令、结果和证据见 [测试记录](arsim-validation-20261118.md)。

状态含义：**已修复**表示本次已修改工具或配置并有对应验证；**已绕过**表示当前测试可继续，根因或通用处理仍未解决；**待优化**表示现有能力或风险仍需后续处理。

| 问题 | 状态 | 本次处理和验证 | 后续优化 |
| --- | --- | --- | --- |
| 仿真只能依赖预先存在的 `ar000loader.exe`，无法按 RUC 自行准备工作目录 | **已修复** | 新增 `plc_provision_arsim`；`arsim_work_dir` 可配置，缺省为 `.apj` 目录下的 `Temp/Simulation`，每次安装进入独立子目录。AS4、AS6 均以默认目录实际安装和运行；自定义目录通过自动化检查。 | 可增加受控的实例复用、停止和状态查询能力；保留已有数据和实例归属校验。 |
| AS4 与 AS6 的 RUC 离线安装命令不同 | **已修复** | 按工具链版本分别使用 AS4 `CreateARsimStructure` 和 AS6 `OfflineCommissioning`；两套 RUC 均实际安装成功。 | 扩大 AS / AR 版本覆盖，不将本次两个版本的结果推广到所有版本。 |
| AS4 首次启动时未使用目标 IP，误绑定 `127.0.0.1` | **已修复** | p801 设置 `SimulationIPAddress=127.0.0.2` 并重新构建后，与 AS6 的 `127.0.0.1` 同时运行；工具增加地址一致性检查、错误地址检测及失败进程清理。 | 改善提示或自动编排：先检查工程配置，再由 AI 按授权修改并重建；当前工具不会自动修改工程地址。 |
| 缺少统一的 IP 冲突检查 | **已修复（限定检测范围）** | 融合 p802 占用判定，提供 `plc_check_arsim_occupancy`；双实例运行时识别两者占用，重复使用 `127.0.0.2` 被拒绝。 | 采样只覆盖登记端口且不是预约；外部进程仍可能在采样后抢占地址。可进一步研究跨进程预约、失效恢复及更多端口。 |
| AI 缺少简短的工具使用说明 | **已修复** | 新增 17 行 [br-plc-toolchain Skill](../.agents/skills/br-plc-toolchain/SKILL.md)，覆盖构建、安装、反馈和重试边界；Skill 结构检查通过。 | 根据后续实际使用反馈调整，不依赖 Skill 代替 MCP 内的安全检查。 |
| AS4、AS6 并行构建返回错误 9207 | **已绕过** | 等待 AS6 构建结束后串行重试 AS4，两者均成功。 | 在工具链中增加跨工程构建排队或明确返回可重试的构建占用状态；当前没有自动排队。 |
| 两个在线下载的日志显示成功，但包装进程未在宽限期退出 | **已绕过** | 工具依据成功日志清理进程树并重新探测；两套程序随后均经独立 PVI 查询确认 RUN 和变量值。 | 排查 PVITransfer / 包装进程不退出的原因，区分传输成功、清理成功和应用验证成功。 |
| 旧 `arsim_loader_exe` 指向其他运行目录，且安全检查报 `Get-FileHash` 不可用 | **已绕过** | 从 p801 的本地配置移除旧 loader 指向后，安全检查和下载继续完成。 | 复现并修复 `Get-FileHash` 不可用的根因；加强在线目标与实际运行目录的归属核验，不能根据旧路径推断当前实例身份。 |
| 旧 `access_policy` 字段与当前项目配置格式不兼容 | **已绕过** | 两个测试配置中移除已废弃字段后，当前 MCP 服务能够加载配置。 | 提供明确的配置迁移提示与权限语义对照；旧字段不能直接代表当前服务中的写入约束。 |
| ARsim 的 PVI 写入列表未按配置限制 | **待优化** | 当前运行时允许对可写 ARsim 变量使用 `execute=true` 写入，忽略 PVI 写入列表；本次测试只读取，没有写变量。 | 明确 ARsim 的默认和显式白名单 / 黑名单语义，补充测试并同步文档。 |
| 下载安全检查对部分缺失或不一致的元数据给出告警 | **待优化** | 本次通过独立运行目录、进程和 PVI 地址确认目标归属，并检查传输日志；告警本身仍存在。 | 改进运行实例身份、配置 ID、分区等证据采集；不能将 `ok=true` 等同于所有兼容项都已确认。 |
| 此前下载安全检查设置 20 秒后，MCP 35 秒仍未返回 | **待排查** | 当时终止了等待；本次在仿真运行后安全检查返回。两次条件不同，不能认定原超时问题已修复。 | 检查客户端、服务端和子进程的超时与取消传播，覆盖目标不可达及清理失败场景。 |
| AS4 / AS6 PVI 版本切换及新工具发现依赖服务进程生命周期 | **待优化** | 本次通过独立的 PVI4、PVI6 MCP 服务进程完成查询；新代码通过新启动服务测试。 | 改善多版本进程管理和工具刷新；已运行的旧 MCP 服务需重启或重新加载才能发现新增工具。 |

本次未验证真实 PLC、所有业务功能或未登记端口；不得用这次 ARsim 结果替代这些验证。
