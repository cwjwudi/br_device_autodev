### 根因发现：PVI 试用版 2 小时时限
- **Pvi6Man.exe 运行超过 2 小时后，PVI 全部连接失败**（`plc_discover_runtime_target` 连接失败的直接原因）。
- 已检测到 PVI 运行 1058 分钟（17.6h）远超 2h → 自动重启（Stop-Process + Start-Process，旧 PID 17640 → 新 PID 2652），重启后 Pvi.py 连接恢复（manager=True, cpu_err=0）。
- **沉淀脚本 `scripts/pvi_watchdog.py`**：检测 Pvi6Man 运行时长，超 2h 自动重启并验证 Pvi.py 连接；`--check` 仅报告。以后遇到 PVI/PVITransfer 连接失败先跑它。

### 锁残留根因（重要）
- WorkBuddy 全局注入 safe-delete hook：**所有 Python unlink 被劫持**（`SAFE_DELETE_FAIL_CLOSED`，回收站不可用），**提权运行也拦**（是进程内 hook 非文件系统权限）。
- 工具链 `FileLock.release()` 的 `except OSError: pass` 吞掉 → 每次 target_change 工具后锁残留 → 后续工具 LOCK_CONFLICT。
- **清理锁只能用 Git Bash `rm -f`（POSIX 实现不受 hook 影响）；不能用 Python `Path.unlink`/`shutil.rmtree`。**
- 教训：`rm ... && python ...` 链式命令可能因 rm 触发 hook 失败而短路；清锁与跑测试分开执行。
